# What the feasibility pilot tests

A native Codex session has normal repository tools. B adds the existing flat BM25 MCP. C adds its relation-aware reranker with file/module/local-call hints. Source, API, response caps, model, effort, prompt, one-attempt policy and wall ceiling are matched. This is the existing engine carried into a feature-level runtime, not an implemented contract/invariant reasoning engine.

Record official whole-instance resolution, partial F2P test pass fraction, P2P preservation, token usage, MCP consultation, wall time and infrastructure failures. Unknown provider-dollar cost remains null. Setup/dependency acquisition is separate from the five-minute agent execution ceiling; all three arms install the same isolated packages. The deadline is an outer in-container timeout; no controlled token/dollar ceiling is claimed.

A calibrated failure audit should distinguish requirement omission, localization, implementation, tool/runtime and unknown causes. No independent rubric reviewers are currently available; initial classifications are author diagnostics. Hidden tests are revealed only to the evaluator after the patch is sealed. Preserve all scheduled outcomes and blocked tasks.

The next contract engine would encode public requirement → observable interface → dependency → verification obligation, with exact permitted-input citations and revision invalidation. Its effectiveness is a new experiment, not retrospectively inferred from this pilot.
