# Feature-level contract pilot

Out of Distribution Labs · October 7, 2026 (Pacific)

Primary question: does relation-aware evidence improve complete feature implementation relative to a strong flat tool at matched resources? First qualify assets and failure mechanisms. This is a development/feasibility pilot, not a powered test or SOTA claim. Preserve the prior frozen negative retrieval assay.

Start with up to two deterministically selected v1.1 Fast lv1 instances from different repositories, selected before any agent outcomes. Run native, flat and graph arms in fresh sessions, one attempt per arm, model `gpt-6.1-sol` with `medium` reasoning effort, 300-second agent wall ceiling, at most six runs. Account inference tokens, engine time and official score. ChatGPT-authenticated Codex only; do not introduce paid API credentials. Stop for quota errors or invalid isolation. Small n cannot establish a five-point benefit.

The existing lexical engine is a transport/decision-support baseline, not yet the proposed contract engine. Inspect bounded pilot trajectories to decide whether richer requirement/dependency obligations are justified. Gold and hidden test patches are evaluator-only. Agent environment must be stripped of them and lack unrestricted shell access to the host evaluator. Any local-adapter mismatch is disclosed.

Sentinel after every checkpoint: author self-review, artifact hashes, advance/redo/hold decision. Failures are retained; no outcome-based task replacement. Pages every 60 seconds, ntfy every 300 seconds.

Storage deviation: derive single-layer images from immutable official filesystem exports to fit VFS. Preserve runtime configuration, record source/derived digests, qualify with unchanged official scorer. This is not an official leaderboard run.
